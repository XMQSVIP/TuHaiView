# 原生网格上传内存诊断

本次修改针对重复上传 egui 顶点／索引时的原生内存增长。诊断程序与产品分开构建，没有读取图库。以下每项均独立运行 180 秒连续绘制、随后 30 秒空闲，窗口未最小化；斜率取第 1、2 分钟 private bytes 中位数差，属于短诊断。

| 条件 | 活跃帧数 | private bytes 变化 MiB／分钟 |
| --- | ---: | ---: |
| 固定英文控件，原上传路径 | 144,928 | +9.121 |
| 空白画面 | 527,954 | −0.047 |
| 空白，每帧两次 64 KiB Queue 缓冲上传 | 430,996 | +27.289 |
| 相同空白与上传量，StagingBelt 复用 | 439,098 | −0.051 |
| 固定英文控件，网格上传复用 | 144,349 | −0.055 |

独立变量对照支持将修复放在频繁缓冲上传路径：没有以更高内存预算、更低图片质量或更小测试集换取稳定性。原生对象数稳定并不代表进程 private bytes 稳定，也不能据此把问题归因到某个特定驱动。完整数据见 `renderer-*.json`；`renderer-probe-provenance.json` 保存每轮二进制、参数、日志位置及哈希。

修改使用固定版本 egui-wgpu 0.31.1 的本地补丁，来源、许可证和生命周期说明见 `vendor/egui-wgpu/TUHAI-PATCH.md`。原生 winit 绘制使用 256 KiB StagingBelt，直接填入映射区，提交前结束写入；下一帧异步回收已提交或丢弃编码器的缓冲。其他集成路径保持原实现。默认 Mailbox、图片解码／上传／缓存／纹理预算未调整。

StagingBelt 的原生缓冲池按需要增长、保留可复用块；256 KiB 是分配块尺寸，**不是缓冲池总上限**，也不属于 256 MiB 图片纹理租约。最小控件探针的 HAL 缓冲数稳定为 8、总缓冲字节为 1.5 MiB；不能把这一数字外推成产品或驱动的内存硬上限。GPU 堵塞和复杂网格需要继续观察。

GPU 回归连续 32 帧比较旧上传和复用路径，逐像素一致；每四帧丢弃一次未提交的上传编码器，再次绘制仍一致。产品 Release 功能回归 40 通过、0 失败、5 个手动测试默认忽略，图片分片上传／取消 GPU 读回单独通过。完整产品连续操作和最终 30 分钟矩阵尚待检验；这些短探针不能标记性能收尾完成。
